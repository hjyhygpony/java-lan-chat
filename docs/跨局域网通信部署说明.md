# 不同局域网之间通信的部署说明

## 一、为什么原来只能在同一局域网通信

客户端填写的通常是 `192.168.x.x`、`10.x.x.x` 或 `172.16.x.x—172.31.x.x` 一类私有地址。这些地址只在所在局域网内部有效，互联网中的另一台机器无法直接访问。

因此，**仅修改聊天代码不能自动穿过两边路由器的 NAT**。要让两个不同局域网中的客户端通信，必须让双方都能访问同一个“公网可达的服务器地址”。

本版本继续采用最适合课程设计演示的“客户端—公网中继服务器—客户端”结构：

```text
局域网A中的客户端 ──互联网──> 公网聊天服务器 <──互联网── 局域网B中的客户端
```

聊天、图片和文件仍由服务器转发，不要求两个客户端彼此直接连接。

## 二、本版本已经做的代码调整

1. 服务器默认绑定 `0.0.0.0`，监听服务器的全部网卡；
2. 客户端支持填写公网 IPv4、IPv6 或域名；
3. 客户端连接设置 10 秒超时，连接失败不会长时间卡住；
4. 客户端和服务器均启用 TCP KeepAlive；
5. 新增 25 秒一次的应用层心跳，降低公网/NAT连接长时间空闲后被关闭的概率；
6. 保留群聊、私聊、好友、资料、图片聊天、图片预览与手动保存、普通文件传输等原功能。

## 三、推荐方案：把服务器部署到有公网 IP 的云主机

### 1. 云主机要求

- Windows Server 或 Linux 均可；
- 安装 JDK 8 或更高版本；
- 具有公网 IPv4、IPv6或可解析到服务器的域名；
- 云平台安全组放行 TCP `3500`；
- 操作系统防火墙放行 TCP `3500`。

### 2. 上传和编译

把整个项目上传到服务器，然后进入项目目录。

Linux：

```bash
chmod +x compile.sh run_server_public.sh
./compile.sh
./run_server_public.sh
```

Windows Server：

```text
双击 compile.bat
双击 run_server_public.bat
```

服务器看到以下提示即表示程序已监听：

```text
绑定地址：0.0.0.0
监听端口：3500
```

### 3. 客户端连接

两台位于不同局域网的电脑都运行 `run_client.bat`，填写相同的服务器信息：

```text
服务器（IP/域名）：云主机公网IP或域名
端口：3500
用户名：两台电脑分别填写不同用户名
```

例如：

```text
服务器：203.0.113.10
端口：3500
```

不要填写云服务器的 `127.0.0.1`，也不要填写它的 `192.168.x.x` 内网地址。

## 四、没有云服务器时：路由器端口映射

可以把其中一台电脑作为服务器，但该局域网需要具备可从互联网访问的公网地址。

1. 固定服务器电脑的局域网地址，例如 `192.168.1.20`；
2. 在路由器中添加端口转发：

```text
外部TCP 3500  →  192.168.1.20:3500
```

3. 服务器电脑运行 `run_server_public.bat`；
4. Windows 防火墙放行 TCP 3500；
5. 外网客户端填写路由器的公网 IP，而不是 `192.168.1.20`。

若运营商使用 CGNAT，路由器 WAN 地址不是独立公网地址，普通端口映射通常无法从外网访问，此时使用云服务器或 TCP 内网穿透服务。

## 五、使用 TCP 内网穿透

也可以使用支持 TCP 转发的 FRP、ngrok 等工具，把本机 `127.0.0.1:3500` 映射成公网地址和公网端口。

聊天服务器仍在本机运行，客户端填写穿透工具提供的公网主机和公网端口。不同工具的账号、配置和公网端口不同，本项目不把第三方账号密钥写入代码。

## 六、连通性检查

在客户端电脑先测试端口是否可达。

Windows PowerShell：

```powershell
Test-NetConnection 公网IP或域名 -Port 3500
```

结果中的 `TcpTestSucceeded : True` 表示网络端口可达。

如果为 `False`，优先检查：

1. 服务器程序是否正在运行；
2. 客户端填写的是否为公网 IP/域名；
3. 云安全组是否放行 TCP 3500；
4. 服务器系统防火墙是否放行；
5. 路由器端口映射是否正确；
6. 是否处于 CGNAT 环境。

## 七、安全说明

当前课程设计协议是普通 TCP，自定义帧未加密。它适合教学、答辩和受控测试，不应直接用于传输密码、身份证件或其他敏感信息。正式互联网产品应增加账号认证、TLS 加密、文件类型与病毒检查、消息存储保护及限流机制。
