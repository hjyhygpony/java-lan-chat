# 参考程序实现方式说明

## 一、修改目标

New Compression 原来使用“整型命令编号 + DataInputStream/DataOutputStream 二进制帧”的方式。现在已经改为“实验三：聊天工具-给学生版”中的文本消息处理结构。

## 二、实现对应关系

| 参考程序结构 | 修改后 New Compression |
|---|---|
| `ClientMsgSender` | 客户端独立发送线程，维护 `LinkedList` 队列 |
| `ClientMsgListener` | 客户端独立接收线程，持续读取完整消息 |
| `ServerMsgSender` | 每个客户端连接对应一个服务器发送线程 |
| `ServerMsgListener` | 每个客户端连接对应一个服务器接收线程 |
| `ConnectionKeeper` | 保存所有连接，执行广播、查找与私聊转发 |
| `BroadcastCommandParser` | 解析昵称、私聊、好友、资料、文件和退出命令 |
| `0xFF` | 每条消息的结束标志 |
| `0xFD` | 命令消息的起始标志 |

## 三、为什么没有逐字照搬原代码

参考程序按单字节写入字符，中文会被截断；线程停止使用了已经废弃的 `Thread.stop()`；同时原程序没有图片、文件、好友和个人资料的完整实现。因此本项目保留其核心架构，但进行了以下必要修正：

1. 普通消息按 UTF-8 字节发送；
2. 命令参数采用 Base64，避免中文、空格、换行破坏命令分隔；
3. 文件先转为 Base64 文本，再放入命令消息；
4. 使用 `wait/notify` 驱动消息队列，避免原程序每 10ms 轮询；
5. 使用正常的线程退出和 Socket 关闭，不调用 `Thread.stop()`；
6. 增加最大消息帧和最大文件限制。

## 四、消息示意

普通群聊消息：

```text
UTF-8正文 + 0xFF
```

命令消息：

```text
0xFD + 命令名称 + 制表符 + Base64参数 + 0xFF
```

例如设置昵称在逻辑上表示为：

```text
0xFD nick <Base64用户名> 0xFF
```

私聊、好友、资料、图片和文件都通过同一套命令解析机制完成。
